# v1.1.0 — Dashboard Pivot

**Status:** DRAFT 2026-08-18 (waiting on David's sign-off)
**Goal:** Replace MC's chat-as-main-window design with a dashboard launcher. The dashboard shows tiles for available apps; clicking the OpenClaw tile opens OpenClaw's existing webview UI in a child window, fully logged-in via the MAIC session we already created. We don't fork or modify OpenClaw — we just wrap it.

**Why:** OpenClaw is open source, actively maintained, and better than anything we'd build in the same time. Wrapping it lets us ride upstream improvements for free, drops our chat-UI build scope to zero, and turns MC into a platform (the dashboard) instead of a feature (a chat client).

**Non-goals for v1.1.0:**
- Pricing tiers, plan badges, billing UI, Stripe integration. (v2)
- More than one dashboard tile. (v2)
- Custom OpenClaw rebrand. (v2)
- OpenClaw configuration UI. Users can edit `openclaw.json` directly if they want; we don't expose it.

---

## 1. Architectural shift (mental model)

**v1.0.4 (today):** MC main window = login screen → chat UI hosted at localhost:28789 inside the same window via `window.location.href`. User sees the OpenClaw chat inside the MC window.

**v1.1.0 (proposed):**
- MC main window = **dashboard** (login screen until MAIC auth, then a tile grid).
- Dashboard has one tile in v1.1.0: **OpenClaw**.
- Clicking the OpenClaw tile spawns a **separate OS-level window** (Tauri WebviewWindow) that loads `http://localhost:28789/`. That window looks and behaves like v1.0.4's main window — same OpenClaw UI, same auth, same chat.
- The dashboard window stays open. User can close the OpenClaw window and reopen it from the dashboard. User can also close the dashboard; closing the dashboard closes the launcher sidecar and stops the gateway.

This is a **multi-window Tauri app**, not a router inside one window. Multi-window is dramatically simpler than building tabs/embedded-iframes, and matches user mental models better (each app is its own window, like Slack windows or Discord servers).

---

## 2. What's dropped from the v1.0.4 → v1.1.0 transition

**Drop:**
- The `window.location.href = "http://localhost:28789/"` redirect in `main.js` (lines 117+). The dashboard doesn't navigate; it spawns a window.
- The `frame-src http://localhost:28789` CSP clause for the main window. (Still needed for the OpenClaw *child* window, but not for the dashboard.)
- Any future chat-UI work I was about to do (conversation history, streaming, message bubbles). **All gone.** OpenClaw owns chat.
- The `connect-src http://localhost:28789` clause from the main window's CSP. The dashboard doesn't talk to the gateway.

**Keep (unchanged):**
- All MAIC auth code: `maic_login`, `first_run_report`, `ensure_maic_provider_config`, `replace_secret_ref_with_literal`, the `normalize_maic_base_url` / `upgrade_legacy_maic_base_url` / `strip_trailing_v1` helpers, and the `auto_relogin` module.
- The launcher sidecar (miracle-claw-launcher.exe) and its spawn logic in `spawn_launcher_and_wait`.
- The bundled resources (openclaw.mjs, node.exe, node_modules, maic-plugin). Same content, same `npm-shrinkwrap.json` pin.
- The `tool_execution: "client"` semantics — still relevant for any client that talks to MAIC directly, even though we won't be that client anymore.
- The baseUrl `/v1` fix from v1.0.4. Critical — without it, the spawned OpenClaw window would still hit the same 404.

**Reuse (small adjustments):**
- `start_gateway_after_login` is still the post-login spawn trigger, but now it just brings up the gateway; the dashboard's tile-click handler spawns the *window*.
- The login screen in `renderLogin()` becomes the first thing the dashboard shows when `needs_maic_login === true`. No more `window.location.href` to the gateway after login.

```js
function renderDashboard() {
  root.innerHTML = `
    <div class="dashboard">
      <header class="dashboard-header">
        <h1 class="logo">MiracleClaw</h1>
        <button id="logout-btn" class="logout" title="Sign out of MAIC">Sign out</button>
      </header>
      <main class="dashboard-grid">
        <button class="tile" data-app="openclaw">
          <div class="tile-icon">🦞</div>
          <div class="tile-title">OpenClaw</div>
          <div class="tile-desc">Chat with MAIC models</div>
        </button>
      </main>
      <footer class="dashboard-footer">
        <span class="muted small">Signed in to ${escapeHtml(/* maic endpoint from report */)}</span>
      </footer>
    </div>
  `;

  document.querySelectorAll(".tile").forEach((tile) => {
    tile.addEventListener("click", () => openApp(tile.dataset.app));
  });

  document.getElementById("logout-btn").addEventListener("click", logout);
}

async function openApp(appId) {
  if (appId === "openclaw") {
    try {
      await invoke("open_openclaw_window");
      // Window is now open; user can close dashboard if they want.
    } catch (e) {
      showFatal(`Could not open OpenClaw: ${escapeHtml(e)}`);
    }
  }
}

async function logout() {
  try {
    await invoke("maic_logout");
    location.reload(); // back to login screen
  } catch (e) {
    showFatal(`Logout failed: ${escapeHtml(e)}`);
  }
}
```

### 3.4 `src-tauri/src/lib.rs` — add `open_openclaw_window` and `maic_logout` commands

**`open_openclaw_window`** — new Tauri command:

```rust
#[tauri::command]
fn open_openclaw_window(
    app_handle: tauri::AppHandle,
    state: tauri::State<'_, AppState>,
) -> Result<(), String> {
    use tauri::{WebviewUrl, WebviewWindowBuilder};

    // If the openclaw window is already open, focus it instead of spawning a second.
    if let Some(existing) = app_handle.get_webview_window("openclaw") {
        existing.set_focus().map_err(|e| e.to_string())?;
        return Ok(());
    }

    // Ensure the gateway is up. If setup() didn't spawn it (login was via dashboard
    // bootstrap, not login screen), spawn it now.
    let key_present = std::env::var(ENV_VAR_NAME)
        .ok()
        .map(|s| !s.trim().is_empty())
        .unwrap_or(false);
    if !key_present {
        return Err(
            "open_openclaw_window: MAIC_API_KEY not set; user must log in first."
                .to_string(),
        );
    }
    // Check if a launcher is already running (the gateway is bound).
    // If not, spawn it. We use a quick TCP probe to localhost:28789 to decide.
    if std::net::TcpStream::connect_timeout(
        &std::net::SocketAddr::from(([127, 0, 0, 1], OPENCLAW_PORT)),
        std::time::Duration::from_millis(100),
    ).is_err() {
        spawn_launcher_and_wait(&app_handle, OPENCLAW_PORT, Duration::from_secs(15))?;
    }

    WebviewWindowBuilder::new(
        &app_handle,
        "openclaw",
        WebviewUrl::External("http://localhost:28789/".parse().unwrap()),
    )
    .title("OpenClaw — MAIC")
    .inner_size(1200.0, 820.0)
    .min_inner_size(800.0, 560.0)
    .resizable(true)
    .center()
    .build()
    .map_err(|e| {
        eprintln!("[miracle-claw] open_openclaw_window build failed: {}", e);
        format!("openclaw window build failed: {e}")
    })?;

    Ok(())
}
```

**`maic_logout`** — new Tauri command:

```rust
#[tauri::command]
fn maic_logout(
    app_handle: tauri::AppHandle,
    state: tauri::State<'_, AppState>,
) -> Result<(), String> {
    use zeroize::Zeroize;

    // 1. Kill the launcher sidecar if it's running.
    if let Some(child) = state.launcher_child.lock().unwrap().take() {
        let _ = child.kill();
        let _ = child.wait();
    }

    // 2. Close the openclaw window if it's open.
    if let Some(w) = app_handle.get_webview_window("openclaw") {
        let _ = w.close();
    }

    // 3. Wipe the keychain entry (stashed email|password from auto_relogin).
    //    Use the same keychain helper from auto_relogin.
    crate::auto_relogin::clear_cached_credentials()
        .map_err(|e| format!("clear keychain failed: {e}"))?;

    // 4. Remove the MAIC provider entry from openclaw.json.
    //    Replace apiKey with SecretRef again so a future login can do its job cleanly.
    //    (Mirrors the inverse of replace_secret_ref_with_literal.)
    wipe_maic_provider_from_openclaw_json()?;

    // 5. Unset the env var in our process.
    //    SAFETY: env var unset is async-signal-safe per POSIX.
    unsafe {
        std::env::remove_var(ENV_VAR_NAME);
    }

    Ok(())
}
```

`wipe_maic_provider_from_openclaw_json` is a small helper (~30 lines) that reads `openclaw.json`, sets `models.providers.maic.apiKey` back to `{ "$ref": "env:MAIC_API_KEY" }`, removes the literal JWT, and writes it back. Same defensive I/O as the existing helpers.

### 3.7 CSP adjustments

**Two CSPs now**: one for the main window (dashboard) and one for the openclaw child window.

The main window's CSP can be tightened:

```
default-src 'self'; 
script-src 'self'; 
style-src 'self' 'unsafe-inline'; 
img-src 'self' data:; 
font-src 'self' data:; 
connect-src 'self' ipc: https://ipc.localhost https://maicserver.com;
frame-src 'none'; 
object-src 'none'; 
base-uri 'self'; 
frame-ancestors 'none';
```

We drop `http://localhost:28789` references because the dashboard never talks to the gateway. Tighter = better.

The openclaw window's CSP needs to allow `http://localhost:28789` for everything (script-src, style-src, img-src, font-src, connect-src, frame-src). This is set via `WebviewWindowBuilder`'s `additional_browser_args` or by configuring per-window CSP — **need to verify the Tauri 2 API for this.** If Tauri 2 doesn't support per-window CSP out of the box, we have two options:

(a) Use a single global CSP that allows `http://localhost:28789` everywhere (slightly looser on the dashboard, but no security regression since the dashboard doesn't fetch from there).
(b) Use `additional_browser_args` to inject a per-window CSP header on WebView2 (Windows).

I'd start with (a) for v1.1.0 and document (b) as a v1.1.1 hardening.

## 4. Risks and unknowns (call out before we build)

1. **Tauri 2 per-window CSP** — verifying the API exists. If it doesn't, we fall back to a single CSP and document it.
2. **Launcher spawn race** — if the user clicks the OpenClaw tile very fast (e.g., immediately after login), `setup()` may already have started the launcher via `start_gateway_after_login`. The `open_openclaw_window` command's TCP probe handles this idempotently.
3. **OpenClaw window focus on second click** — if the user closes the OpenClaw window and clicks the dashboard tile again, we need to spawn a new one. The `get_webview_window` check handles reopen correctly (returns None after close, so we always rebuild).
4. **Logout propagation** — if the user logs out of OpenClaw inside its own window (not via the dashboard), does that clear MAIC_API_KEY from the openclaw.json? **OpenClaw's own logout would write a new SecretRef, but our keychain still has the cached email|password.** This is mostly fine — next time the user clicks the OpenClaw tile, our `ensure_maic_provider_config` will detect the SecretRef and prompt for login. We don't try to "fix" OpenClaw's logout.
5. **Multi-monitor / window restore** — Tauri 2's `WebviewWindowBuilder` doesn't restore window position by default. We accept that the openclaw window always opens centered on first launch. Power-user complaint only; not a blocker.
6. **Bundle size** — already 56 MB. v1.1.0 doesn't add new bundled content (dashboard is JS/CSS in the existing `dist/`). Size delta ≈ 0.
