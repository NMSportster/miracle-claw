# Miracle Claw — Milagro Distribution Corp's desktop chat client for MAIC

Native desktop wrapper for [Milagro AI Cloud](https://milagrocloud.com) (MAIC) chat models. Built with Tauri 2 (Rust shell + system webview) and a bundled Node + OpenClaw runtime.

## What this is

Miracle Claw ships a small, fast native window that:

1. Spawns a local OpenClaw gateway (Node.js + bundled MAIC provider plugin)
2. Loads the OpenClaw Control UI in a webview
3. Speaks MAIC's OpenAI-compatible `/v1/chat/completions` API
4. Handles OS-level concerns: installer, auto-updater, code signing, keychain storage, window chrome

## What this is NOT

- Not a chat model. MAIC is the chat model.
- Not a web app. The webview is the host's native renderer; we don't ship an Electron-style bundled Chromium.
- Not a SaaS. The MAIC backend lives at `maicserver.com` (or your own MAIC instance).

## What goes here

- Tauri Rust shell (wraps webview)
- `miracle-claw-launcher` sidecar (Rust, ~200 LoC, std-only) — owns the lookup of the bundled Node runtime + chat gateway bundle and execs it
- Milagro branding (icons, splash, colors)
- NSIS installer config
- CI build scripts (Linux host → Windows installer via Docker + cargo-xwin)

## What does NOT go here

- Chat logic. The bundled chat gateway does that.
- MAIC client wiring. The MAIC plugin does that.
- Tool call dispatch. The MAIC plugin does that.
- Vendored upstream sources. `depot/` is gitignored — it's the bundle staging directory, regenerated by `scripts/bundle-runtime.sh` before each installer build.

## Architecture

```
miracle-claw.exe (Tauri)
  └─ sidecar: miracle-claw-launcher.exe --gateway-port 28789
       └─ node openclaw.mjs gateway --port 28789 --bind loopback --auth none
            └─ WebChat UI on http://127.0.0.1:28789/
                  └─ talks to MAIC via OpenAI-compat transport
                  └─ MAIC plugin (vendored from ~/.openclaw/extensions/maic/) injects
                      tool_execution: "client" automatically
```

First-run path (idempotent):

1. Ensure `~/.openclaw/extensions/maic/` has the bundled plugin files (SHA-256 manifest check; skip-on-match)
2. Ensure `~/.openclaw/openclaw.json` has `pluginRoots` and `plugins.roots` pointing at the user's extensions dir (deep-merge, not overwrite)
3. Spawn the launcher sidecar
4. Poll TCP connect to `127.0.0.1:28789` until bound (15s cap)
5. Show webview (already pointing at `localhost:28789/`)
6. On `RunEvent::ExitRequested`, kill the launcher child

## Build

```bash
# 1. Bundle the OpenClaw + Node runtime into depot/
bash scripts/bundle-runtime.sh

# 2. Build everything (sidecar + main binary)
bash scripts/build-launcher-sidecar.sh
cd src-tauri && cargo build --bin miracle-claw

# 3. Cross-compile a Windows installer from Linux/WSL
bash scripts/build-windows-docker.sh
# → dist-installers/windows/MiracleClaw_<ver>+<n>_x64-setup.exe
```

## Key files

| File | Purpose |
|---|---|
| `src-tauri/src/lib.rs` | Tauri main; runs `setup()` on launch |
| `src-tauri/src/launcher.rs` | Sidecar; `miracle-claw-launcher` binary |
| `src-tauri/src/launcher_info.rs` | Shared constants (port, plugin filenames) |
| `src-tauri/src/provider_keys.rs` | BYO provider key registry + vault (OpenAI, Anthropic, etc.) |
| `src-tauri/src/secrets_encryption.rs` | AES-256-GCM at-rest encryption for the secrets vault |
| `src-tauri/src/auto_relogin.rs` | Silent re-auth on 401 using cached credentials |
| `src-tauri/capabilities/main.json` | Tauri permission allowlist (webview can spawn only the launcher with `--gateway-port N`) |
| `scripts/build-launcher-sidecar.sh` | Stage the sidecar binary for `tauri-build` |
| `scripts/bundle-runtime.sh` | Download + stage OpenClaw + Node into `depot/` |
| `scripts/build-windows-docker.sh` | Cross-compile a Windows installer via Docker + cargo-xwin |
